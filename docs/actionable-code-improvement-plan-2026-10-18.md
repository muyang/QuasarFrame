# QuasarFrame 可执行代码完善方案

更新：2026-10-18。依据当前工作区源码与实测命令制定；仓库既有文档是现状和设想的参考，不作为已实现功能或额外指令。目标是先交付一个**可验证的摄影助手**，再接入**有授权的机位内容订阅**，最后适配电视与数字相框。实体相框型号未定，不阻塞软件端。

## 当前基线与首个可交付版本

- 已有 Next.js 16 / React 19 Web 原型，静态地点、Cesium 地球、Three 示意地形、日月与视场计算、本地拍摄计划、摄像头目录/播放器、上传/会员/相框商城页面。`src/hooks/useCesium.ts` 使用椭球面；`src/components/camera/CameraSimulator.tsx` 的地形由正弦函数生成；`src/components/camera/ShootingPlanner.tsx` 只保存在浏览器。
- 已验证 `node --import tsx --test tests/photography.test.ts` **10/10 通过**，TypeScript `--noEmit` **通过**；`eslint src --quiet` **45 项错误**。本机默认 Node 9，不满足项目运行要求；使用已有 Node 22.22.1 可执行这些检查。本次没有重跑生产构建、真机、支付或摄像头上游联调。
- Git 仅追踪 19 个文件，多数业务源码、文档与测试未追踪；根目录 SQLite 数据库及 `public/uploads` 也未在 `.gitignore` 中排除。原始资料和凭据不可直接批量入库。
- 当前最小可交付版本定义为：用户在**一个经现场核验的机位**选日期、镜头与主体，看到有来源/误差说明的真实地形轮廓和遮挡，能保存并在另一浏览器读取计划；一条**已授权**的实景观测显示采集时间与过期状态。AI 概念图、收费频道和实体硬件不作为这一版本的上线依赖。

## 实施顺序

与此前讨论的三层对应：**第一层可信地理与拍摄计划（P1–P3）→ 第二层 AI 概念模拟（P4）→ 第三层授权机位资源与多屏订阅（P5–P6）**。P0A/P0B 是三层共用的工程和权限底座，先行处理。

| **P0A：固定可复现基线**，所有后续工作的前置，约 1–2 周 | 更新 `.gitignore` 排除数据库/WAL/备份、上传原图和生成地形；整理并纳入 `src/`、`tests/`、配置及文档，检查凭据；补真实 `README.md`、`.env.example`、Node 22 约束和 `test/typecheck` 脚本；把 `db:push` 从共享环境交付流程改为版本化 Drizzle 迁移；建立 CI；修复现有 45 项 ESLint 错误。绝不覆盖当前数据库，先做快照与迁移演练。 | 新目录仅凭仓库和示例配置可安装、迁移、启动、完成类型检查、测试、lint 和生产构建；数据库与用户上传文件不进入提交。 |

## 代码边界与测试安排

在现有 Next.js App Router 下，`src/app/api/**/route.ts` 只处理输入、鉴权和响应；业务规则进 `src/server/{entitlements,places,plans,terrain,observations,playback}`，可复用且易测试；日月/视场/遮挡几何进无数据库依赖的 `src/lib/`。地形预处理、媒体采集和 AI 推理作为离线或后台进程，通过版本化产物和任务状态与 Web 通信。Next 16 的 Route Handler 行为按本仓库 `node_modules/next/dist/docs/01-app/01-getting-started/15-route-handlers.md` 核对后实施。

每个代码包至少包含：数据库迁移及回滚/备份说明、领域单元测试、涉及鉴权的 API 集成测试、失败路径和观测字段。P2 另用固定 DEM 小样本测试坐标/高度基准与无数据处理；P5/P6 另做断流、过期、撤权与多端播放测试。CI 应持续运行类型检查、现有摄影测试、lint、迁移烟测和生产构建；真实外部摄像头/支付只在隔离试点环境联调，不让 CI 依赖其可用性。

## 排期与外部输入

以约两名开发者为粗估：P0A/P0B 先做 2–4 周；P1–P3 再用约 4–6 周形成地形摄影助手；P4 与 P5 各约 1–3 周并行试验；P6 在授权内容稳定后约 2–4 周。不是固定交付承诺，现场核验、许可、模型选择和终端兼容可能改变工期。

工程可立即开始 P0A、P0B 中的安全修复，以及 P1 的模型设计。外部必须补齐的四项输入是：**首个真实机位及对照照片**、**现有摄像头二次分发授权范围**、**采集到展示的可接受延迟**、**首个电视/相框终端的能力档案**。前三项分别决定地形验收、内容上架和“实时”阈值；相框型号未定时先用浏览器模拟协议。
